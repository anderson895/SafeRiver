# SafeRiver — System Documentation

**Web-Based Flood Hazard Information and Dam Release Alert System for Agno
River Communities in San Manuel, Pangasinan**

Live: <https://safe-river-san-manuel.vercel.app>

Screenshots referenced below are generated by `npm run screenshots` into
`screenshot/<desktop|mobile>/<en|tl>/`.

---

## 1. What the system does

It gathers official flood-related information for San Manuel and presents it in
one place, in English and Tagalog, on any browser.

It does **not** run a flood simulation. It relays what PAGASA, Project NOAH and
other agencies publish, and warns residents by email when conditions change.

**Why San Manuel specifically.** The municipality sits on the Agno River. Three
dams sit along that river — Ambuklao and Binga in Benguet, and San Roque inside
San Manuel itself. Heavy rain over the Cordillera makes the upstream dams
release; that water collects in San Roque; when San Roque opens its gates the
discharge raises water levels across the low-lying barangays. The delay between
an upstream release and the water arriving is warning time, and capturing it is
the point of the system.

## 3. How alerts work

A scheduled job checks conditions every 30 minutes and decides whether anything
is worth telling people.

### Thresholds

Reservoir level, as offsets from each dam's own spilling level (NHWL), so the
same rule serves all three dams:

| Condition | Severity |
|---|---|
| Level ≥ NHWL − 5 m, **or** 24-hour rise ≥ 2.0 m | ADVISORY |
| Level ≥ NHWL − 2 m, **or** 24-hour rise ≥ 4.0 m | WATCH |
| Level ≥ NHWL | WARNING |
| Level ≥ NHWL + 0.5 m | CRITICAL |

Release, for San Roque (upstream dams use 60% of these, as leading indicators):

| Condition | Severity |
|---|---|
| Any gate open, **or** ≥ 500 CMS | ADVISORY |
| ≥ 1,000 CMS | WATCH |
| ≥ 2,500 CMS | WARNING |
| ≥ 5,000 CMS | CRITICAL |

Rainfall follows PAGASA's published scale: Yellow 7.5–15 mm/hr, Orange 15–30,
Red above 30.

**Compound escalation.** When rainfall and a release are both elevated,
severity is raised one level. Saturated ground plus a dam release is the
documented Agno flood mechanism, and either alone understates the risk.

### Not sending is as important as sending

The bulletin is re-read 48 times a day. Without controls, subscribers would be
emailed every 30 minutes for an unchanged condition, and would stop reading.

- Worsening conditions send immediately.
- The same severity re-sends only after a cooldown (12/6/3/1 hours by severity).
- Improving between two active levels is recorded silently.
- An all-clear needs two consecutive clear readings, so a single blip cannot
  cancel a warning.
- Maximum 6 emails per subscriber per day. A runaway rule degrades to silence,
  not to spam.

Verified against live data: four alerts fired for the Ambuklao and Binga
releases; re-running the job raised the same four signals and sent nothing.

### Manual advisories

San Roque announces actual gate releases on Facebook and in PDFs, which cannot
be read automatically. The admin console lets a DRRM officer post a real release
as it happens, prefilled from the live reading so figures are confirmed rather
than retyped.

## 5. Technology

Next.js and React with TypeScript, Material UI, MapLibre GL JS for maps,
Firebase Firestore for storage, Nodemailer with Gmail SMTP for alerts, hosted
free on Vercel.

Scheduling runs on GitHub Actions rather than Vercel cron, because Vercel's free
plan allows only one cron run per day — too coarse for a flood system. All
server logic sits in Next.js API routes rather than Firebase Cloud Functions,
which now require a paid plan; this keeps Firebase on the free tier.

Everything runs at zero cost.

## 6. Testing done

**75 automated tests** covering the parts where a bug is invisible until it
matters:

| Area | What is checked |
|---|---|
| Alert engine | Thresholds, deduplication, cooldown, all-clear, compound escalation, and a simulated full day of polling asserting a sustained condition cannot spam |
| Subscription tokens | Signing, expiry, tamper resistance, and that a confirm link cannot be replayed as an unsubscribe |
| Rainfall units | Every band pinned to mm/hr |

**Verified against live systems**, not mocks: the PAGASA scraper against the
live page, alert firing and suppression against real dam readings, subscription
and confirmation end to end, and email delivery to a real inbox.

The map build verifies itself — `npm run gis:build` fails if hazard geometry
escapes the municipal boundary.

## 7. Limitations

Each figure was measured against the data the system uses, not taken from what
the sources claim. All are stated publicly on the About page.

**Two-thirds of San Manuel has no hazard mapping.** Barangays San Roque, Lapalo
and Narra are 0%, 3% and 1% covered. They are hatched on the map, because a
blank area reads as "safe" and here it means "never surveyed".

**Hazard mapping is 30 metres**, measured from the geometry: 97.5% of 35,322
segments are exactly 30.0 m. The upstream description credits 1 m LiDAR as
modelling input, but the published product is 30 m. The system indicates
whether an *area* is at risk, not a house.

**Dam readings are published once a day**, around 08:00. A release between
bulletins does not appear until the next one, or until an officer posts a
manual advisory.

**There is no river gauge** for the Agno at San Manuel. Water levels shown are
reservoir elevations. The river discharge figure is modelled at ~5 km
resolution.

**Rainfall is modelled, not measured.** DOST-ASTI operates rain gauges but
exposes no public API.

**Alert thresholds are provisional**, pending validation with the San Manuel
MDRRMO.

**Boundaries are generalised.** GADM puts San Manuel at 119.1 km² against an
official 129.18 km².

**Email capacity is ~400/day.** Sufficient for an evaluation cohort, not for the
whole municipality. Migrating is a change of three environment variables.

## 8. Running it

```bash
npm install
cp .env.example .env.local     # fill in
npm run dev
```

| Command | Purpose |
|---|---|
| `npm test` | Run the test suite |
| `npm run screenshots` | Regenerate documentation images |
| `npm run docs:docx` | Build `documentation.docx` from this file + screenshots |
| `npm run gis:build` | Rebuild hazard layers from source data |
| `npm run db:status` | Show what is stored |
| `npm run alert:test` | Fire a test alert end to end |
| `npm run admin:grant -- email@example.com` | Grant admin access |

Deployment is automatic: pushing to `main` deploys to Vercel.

**Two settings matter in production.** `ALERTS_ENABLED` must be `true` or no
email is sent, and `NEXT_PUBLIC_SITE_URL` must be the production URL, since
unsubscribe links are built from it.

## 9. Privacy

Subscriber email addresses are personal data under the Data Privacy Act of 2012
(RA 10173). The system stores the address, language, barangay if given, and the
date, time and IP address of consent — the last so that consent is
demonstrable, as the Act requires.

Addresses are used only for flood alerts. Every message is sent individually,
never BCC, so no subscriber sees another's address. Every message carries a
working unsubscribe link. Copies and deletions are provided on request.
